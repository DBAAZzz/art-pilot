# 提示词管理 v2 方案：双模式与灵感集市

## 背景

`提示词管理` v1 已经打通了从 YouMind 导入、保存到 SQLite、在桌面端展示提示词列表和详情的基础闭环。当前页面采用偏 macOS 生产力工具的 master-detail 结构：

```txt
左侧：提示词列表、搜索、数量
右侧上方：预览图、标题、元信息、复制、来源
右侧下方：完整 Prompt 阅读区
```

这个结构适合精读、管理和复制已有提示词，但不适合“逛图找灵感”。用户在缺少明确目标时，更需要通过视觉结果快速扫图、快速判断、快速复制。参考的瀑布流页面本质上是“灵感市场 / 发现页”：图片是主角，Prompt 文本只做辅助，核心路径是看中图片后直接复制 Prompt。

v2 的目标不是推翻当前管理视图，而是在同一个提示词管理页面内引入双模式：

```txt
列表视图：管理、定位、精读、确认
画廊视图：浏览、筛选、快速复制
```

## 目标

- 保留当前列表详情结构作为默认管理视图。
- 增加 `列表 / 画廊` 视图切换。
- 画廊视图使用浅色瀑布流布局，强化预览图和一键复制。
- 列表视图增加更前置的复制入口，减少复制 Prompt 的操作路径。
- 画廊视图提供轻量筛选：分类、来源、语言、有图/全部。
- 搜索和筛选逻辑在列表与画廊之间保持一致，不维护两套结果集。
- 不改变 Electron 的 renderer / preload / main process 边界。
- 不新增数据库字段，优先复用现有 `PromptRecord`。

## 非目标

- 不做独立 Marketplace 路由。
- 不做暗色沉浸画廊；v2 先保持当前应用的浅色工具气质。
- 不做在线提示词市场、远程分页、账号同步或推荐算法。
- 不做复杂 Prompt 编辑器。
- 不缓存远程预览图到本地。
- 不重构提示词导入、保存、数据库或 IPC 结构。
- 不把复杂筛选塞进列表左栏，避免管理视图拥挤。

## 核心决策

推荐采用同页双模式切换：

```txt
PromptManagementPage
  -> PageToolbar
       搜索、数量、列表/画廊切换
  -> ListView
       左侧列表 + 右侧详情
  -> GalleryView
       顶部筛选 + 瀑布流卡片
```

理由：

- 当前数据是个人提示词库，不是公共市场；独立发现页会让产品结构过重。
- 管理视图和浏览视图服务的是不同心智，不应互相挤压空间。
- 同页切换能共享搜索、筛选、复制反馈、图片预览和错误处理。
- 浅色画廊与当前应用保持统一，降低视觉跳变。

## 页面信息架构

页面仍然位于现有 `提示词管理` 路由。全局 `AppHeader` 保持只显示页面标题。

提示词页面内部增加轻量工具栏：

```txt
搜索框 | 结果数量 | 列表 / 画廊
```

工具栏归属于提示词页面内容，不放进全局 Header。这样不会影响其他页面，也符合当前页面级功能的边界。

### 列表视图

列表视图继续采用当前 master-detail 结构：

```txt
左侧列表
  - 标题
  - 提示词条目
  - hover 复制

右侧详情
  - 大图预览
  - 分类、标题、描述
  - 来源、更新时间、作者、语言
  - 复制提示词
  - 原始来源
  - Prompt 完整内容
```

列表视图不增加复杂筛选。它的定位是“管理和精读”，需要保持安静、稳定、可长时间使用。

### 画廊视图

画廊视图占据提示词页面主内容区：

```txt
顶部筛选条
  - 分类胶囊
  - 来源
  - 语言
  - 全部 / 有图

瀑布流卡片
  - 预览图
  - 标题
  - Prompt 或描述摘要
  - 分类标签
  - 复制 Prompt
```

画廊视图的核心动作是“看中即复制”。图片点击打开现有大图预览；复制按钮不进入详情；标题或更多入口用于回到列表详情查看完整内容。

## 列表视图完善

### 列表项

列表项继续显示首张预览图、标题、描述或 Prompt 摘要、少量分类、来源和更新时间。

改进点：

- 图片尺寸固定，避免列表滚动时布局跳动。
- 标题限制 1-2 行，描述限制 2 行。
- 分类最多显示 2-3 个，更多分类不在列表项展开。
- 来源和时间弱化为底部辅助信息。
- hover 时出现复制图标按钮，点击后复制完整 Prompt。

hover 复制不改变当前选中项。用户可以在列表中快速拿走多个提示词，不被详情切换打断。

### 详情区

详情区保留当前信息密度：

- 大图预览仍然是右侧上方的主要视觉锚点。
- 元信息卡片继续展示来源、更新时间、作者、语言。
- 主复制按钮继续保留，并显示 `已复制` 短反馈。
- 原始来源按钮仍然使用 `window.api.openExternalUrl()`。
- Prompt 区用于完整阅读，第一版只优化排版和滚动，不加入编辑功能。

## 画廊视图设计

### 筛选条

筛选条只消费现有 `PromptRecord` 字段：

- 分类：来自 `categories` 的去重集合。
- 来源：来自 `sourceSite`。
- 语言：来自 `originalLanguage`。
- 图片状态：`全部` 或 `有图`，由 `previewImages.length > 0` 判断。

筛选交互采用轻量胶囊和小按钮，避免做成复杂后台筛选器。第一版不需要多层下拉或高级搜索语法。

### 瀑布流卡片

卡片以图片为主。对于有预览图的提示词，首张图作为卡片主图；对于无图提示词，显示低强调占位块，仍允许复制。

卡片内容：

- 主图：点击打开 `ImagePreviewOverlay`。
- 标题：点击可切回列表视图并选中该提示词。
- 摘要：优先显示 `description`，没有描述时显示 `content` 的前 1-2 行。
- 标签：展示最多 3 个分类。
- 复制按钮：卡片底部全宽，文案为 `复制 Prompt` 或 `已复制`。

画廊卡片不承载完整 Prompt 阅读，避免长文本破坏浏览节奏。

## 数据流

后端数据流不变：

```txt
PromptManagementPage
  -> window.api.listPrompts()
  -> preload
  -> PromptController
  -> PromptService
  -> SQLite prompts
```

前端派生数据：

```txt
prompts
  + query
  + gallery filters
  -> filteredPrompts
```

`filteredPrompts` 是列表和画廊共用的结果集。搜索框放在页面内部工具栏中，列表和画廊都使用同一个搜索条件。画廊筛选只有在画廊视图中展示；切回列表时可以保留筛选状态，也可以在 UI 中明确显示当前结果数量。

推荐第一版保留筛选状态。这样用户可以在画廊里缩小范围后，点击标题切回列表详情，仍然处在同一批结果中。

## 状态设计

状态保留在 `PromptManagementPage` 内部，不引入全局 store。

核心状态：

```ts
type PromptViewMode = 'list' | 'gallery'

type GalleryFilters = {
  category: string | null
  sourceSite: PromptSourceSite | 'all'
  language: string | 'all'
  imageState: 'all' | 'withImage'
}
```

页面状态包括：

- `prompts`
- `selectedPromptId`
- `selectedImageIndex`
- `query`
- `viewMode`
- `galleryFilters`
- `copiedPromptId`
- `loading`
- `error`

复制动作统一使用 `copyPrompt(prompt)`。列表、详情和画廊都通过同一个 `copiedPromptId` 显示反馈。

## 错误处理

沿用当前页面内错误提示：

- `listPrompts()` 失败：显示读取错误，并保留空状态。
- 复制失败：显示错误文本，不中断当前视图。
- 打开原始来源失败：显示错误文本。
- 图片加载失败：浏览器原生失败状态可先接受；后续可以补 `onError` 占位。

空状态按当前语气处理：

- 无任何提示词：提示暂无已导入提示词。
- 搜索或筛选无结果：提示没有匹配结果，并建议调整关键词或筛选。

## 组件边界

第一版可以继续放在 `apps/desktop/src/features/PromptManagement/index.tsx` 内，但建议按内部组件拆分，避免单文件继续膨胀：

```txt
PromptManagementPage
PromptPageToolbar
PromptListView
PromptListItem
PromptDetail
PromptGalleryView
PromptGalleryFilters
PromptGalleryCard
EmptyState
InfoTile
```

如果实现后文件明显过大，再把画廊相关组件拆到同目录下的独立文件。v2 不做跨 feature 抽象，避免过早抽象。

## 测试与验证

实现后需要执行：

```bash
pnpm typecheck
pnpm --filter @art-pilot/desktop exec vite build
```

需要手动检查：

- 列表视图默认打开，已有选中逻辑正常。
- 搜索结果在列表和画廊一致。
- 列表项 hover 复制不改变选中项。
- 详情复制、画廊复制、列表复制都能显示 `已复制`。
- 画廊筛选能按分类、来源、语言、有图状态过滤。
- 图片点击能打开现有大图预览。
- 标题或详情入口能从画廊回到列表并选中对应提示词。
- 当前窗口宽度下文字不溢出，按钮不挤压，瀑布流卡片稳定。

## 实施顺序建议

1. 增加 `viewMode` 和页面工具栏。
2. 把现有布局包成列表视图，保持行为不变。
3. 给列表项增加 hover 复制。
4. 增加筛选状态和筛选派生逻辑。
5. 实现浅色画廊视图和卡片复制。
6. 接入图片预览与画廊到详情的跳转。
7. 跑类型检查和桌面端 Vite build。

## 验收标准

- 用户默认仍看到熟悉的列表管理视图。
- 用户可以切换到画廊视图，通过图片快速浏览提示词。
- 用户可以在任一视图一键复制完整 Prompt。
- 画廊视图不牺牲详情阅读能力，用户仍能回到列表详情精读。
- v2 不改动主进程、数据库和共享类型结构，除非实现中发现现有类型无法表达必要状态。
