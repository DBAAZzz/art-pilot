# 提示词管理 v3 方案：模板变量体系

## 背景

前面的提示词管理方案主要围绕“保存提示词”和“浏览提示词”展开：

```txt
YouMind URL
  -> 解析提示词
  -> 保存到本地库
  -> 列表 / 画廊中查看和复制
```

这个流程可以完成提示词收藏和复用，但仍然有一个明显问题：很多高质量提示词并不是一次性文本，而是带有可替换参数的模板。

例如：

```txt
Create a portrait of {{name}} in {{style}} style, using {{reference_image}} as character reference.
```

用户真正使用提示词时，需要先填写人物名称、风格、参考图等变量，才能生成稳定结果。因此，提示词管理不应只保存静态 prompt，而应该逐步升级为“提示词模板库”。

同时，原来的“从 URL 导入”功能容易让用户以为产品重点是采集器、爬虫或外部提示词库同步。新的产品方向应弱化“导入”，把 URL 抓取降级为创建模板时的辅助填充能力：

```txt
新建提示词模板
  -> 可选：从 URL 自动填充标题、正文、图片、来源
  -> 用户编辑 prompt
  -> 定义变量
  -> 保存模板
  -> 使用模板时填写变量
  -> 生成
```

## 目标

- 将提示词管理的核心心智从“导入提示词”调整为“创建和使用提示词模板”。
- 支持在 prompt 正文中使用变量占位符，例如 `{{name}}`。
- 变量第一版支持两种类型：文本变量和图片变量。
- 用户使用模板生成前，必须填写所有必填变量。
- URL fetch 仅作为“从链接填充”的辅助能力，用于默认填充表单内容。
- URL 填充后的标题、prompt、描述、图片和来源信息都允许用户继续编辑。
- 同一个来源 URL 可以创建多个不同模板，不再默认使用 `sourceUrl` 强制去重。
- renderer 不直接访问 Node.js、SQLite 或网页抓取逻辑。
- 变量定义、模板保存和生成前校验都保持类型化。
- 模板解析规则在前后端保持一致，避免编辑器预览和主进程生成结果不一致。

## 非目标

- 不做完整提示词市场。
- 不做 YouMind 列表页批量导入。
- 不做全站爬取、定时同步或账号收藏同步。
- 不做复杂变量表达式、条件语法或循环语法。
- 不做高级表单控件，例如 select、number、color、multi-select。
- 不做图片变量的复杂权重、区域蒙版或多模型差异适配。
- 不在 v1 自动缓存远程预览图到本地。
- 不把 URL 作为模板唯一身份。

## 核心决策

提示词管理的核心对象从 `PromptRecord` 逐步升级为 `PromptTemplate`。

URL 抓取不再是主流程，而是模板编辑器里的辅助动作：

```txt
用户点击新建模板
  -> 手动填写
  -> 或点击“从链接填充”
  -> fetch URL 并解析为表单默认值
  -> 用户确认和修改
  -> 保存为模板
```

变量体系成为模板能力的一部分：

```txt
PromptTemplate
  -> content: 带 {{variable}} 的 prompt 模板正文
  -> variables: 变量定义列表
  -> sourceUrl / sourceSite: 可选元数据
```

生成前不直接使用模板正文，而是先进入变量填写流程：

```txt
PromptTemplate
  + variableValues
  -> resolvedPrompt
  + imageInputs
  -> generation request
```

## 推荐交互

### 模板编辑

提示词管理页增加“新建模板”入口。

模板编辑区建议包含：

```txt
基础信息
  - 标题
  - 描述
  - 分类
  - 预览图
  - 来源 URL

Prompt 正文
  - 支持 {{name}} 变量占位符
  - 高亮变量
  - 可检测未定义变量

变量
  - 变量列表
  - 添加变量
  - 编辑变量名称、标签、类型、是否必填、默认值
```

URL 填充入口建议放在新建模板表单中，作为轻量动作：

```txt
从链接填充
  输入 URL
  点击读取
  自动填入标题、描述、prompt、预览图、来源
```

这个动作只改变当前表单草稿，不直接保存。

### 模板使用

用户在列表或画廊中点击“使用”或“生成”时，如果模板包含变量，需要先展示变量填写面板：

```txt
变量填写
  - 文本变量：输入框 / 多行输入框
  - 图片变量：上传或选择参考图
  - 必填变量校验
  - 预览最终 Prompt
  - 生成按钮
```

如果必填变量没有填写，生成按钮不可用，并提示需要补全变量。

如果模板没有变量，可以沿用当前生成流程。

## 变量语法

v1 推荐使用双花括号语法：

```txt
{{name}}
{{style}}
{{reference_image}}
```

变量 key 规则：

- 只允许英文、数字和下划线。
- 必须以英文字符开头。
- 推荐使用小写 snake_case。
- 同一个模板内 key 必须唯一。
- 变量 key 大小写敏感，但 v1 保存时强制要求 key 和占位符都使用小写，避免 `{{Name}}` 和 `{{name}}` 产生误用。

示例：

```txt
Create a cinematic portrait of {{character_name}} in {{art_style}} style.
Use {{character_reference}} as the main visual reference.
```

对应变量：

```txt
character_name      text   required
art_style           text   required
character_reference image  required
```

## 模板解析规则

v1 必须明确区分三种文本：

```txt
template content
  带 {{key}} 的原始模板正文，用于保存和编辑。

preview prompt
  给用户看的最终预览，可以保留人眼友好的变量状态。

generation prompt
  真正传给生成适配器的纯 prompt 文本。
```

推荐解析规则：

- 文本变量有用户填写值时，替换为用户填写值。
- 文本变量没有用户填写值但有 `defaultValue` 时，替换为默认值。
- 必填文本变量没有值时，阻止生成。
- 非必填文本变量没有值且没有默认值时，替换为空字符串。
- preview prompt 中可以对被忽略的非必填文本变量给出弱提示，但 generation prompt 不保留 `{{key}}`。
- 图片变量不会替换成文件名、URL 或 ID。
- generation prompt 中的图片变量占位符替换为空字符串。
- 已选择图片的图片变量，在 preview prompt 中替换为人眼友好的提示，例如 `【参考图：已选 2 张】`。
- 非必填且未选择图片的图片变量，在 preview prompt 和 generation prompt 中都替换为空字符串。
- 解析后需要做简单空白清理，避免出现连续多余空格或多余空行。

模板解析只依赖变量定义和变量值，不读取图片文件内容。图片变量的结构化值通过解析结果里的 `imageInputs` 传给生成适配器。不同模型需要的图片 token、文件路径、base64 或内部 ID，由生成适配层处理，不放在通用模板解析层。

如果后续发现某些模型必须在 prompt 中保留特殊图片 token，可以在解析结果中增加适配器专用字段：

```ts
promptWithImageTokens?: string
```

v1 暂不默认引入该字段，避免模板层与具体模型耦合。

## 变量类型

v1 只支持两类变量。

### 文本变量

文本变量用于替换 prompt 正文中的占位符。

字段建议：

```ts
export type PromptTextVariable = {
  key: string
  label: string
  type: 'text'
  required: boolean
  defaultValue?: string
  placeholder?: string
  description?: string
}
```

渲染规则：

- 如果用户填写了值，使用用户值替换 `{{key}}`。
- 如果用户未填写，但存在 `defaultValue`，使用默认值。
- 如果变量必填且没有值，阻止生成。
- 如果变量非必填、没有填写且没有 `defaultValue`，解析时替换为空字符串。

### 图片变量

图片变量用于生成请求中的参考图输入，不一定直接拼接进 prompt 文本。

字段建议：

```ts
export type PromptImageVariable = {
  key: string
  label: string
  type: 'image'
  required: boolean
  description?: string
  maxCount?: number
  role?: 'reference' | 'character' | 'style' | 'composition'
}
```

渲染规则：

- 使用模板时展示图片选择或上传控件。
- 如果图片变量必填且没有图片，阻止生成。
- 如果 `maxCount` 未设置，默认按 1 张处理。
- 生成请求中将图片变量值作为结构化 image input 传递。
- prompt 正文中可以出现图片变量占位符，但不建议简单替换成文件名。
- generation prompt 中的图片变量占位符替换为空字符串。
- 已选图时，preview prompt 中的图片变量占位符展示为 `【变量标签：已选 N 张】`。
- 非必填且未选图时，preview prompt 中不展示该变量提示。

### 图片变量值来源

v1 不强依赖完整资产管理系统，但必须保证图片变量能在 renderer、main process 和生成服务之间流转。

推荐 v1 使用临时图片输入结构：

```ts
export type PromptImageInput = {
  id: string
  name?: string
  filePath?: string
  dataUrl?: string
}
```

处理方式：

- 用户从本地选择图片后，renderer 生成临时 `id`。
- 如果 Electron 权限允许，优先保存 `filePath`，由主进程或生成服务读取。
- 如果只适合前端持有，可以使用 `dataUrl` 作为临时数据传递。
- `imageIds` 只引用当前使用面板里的临时图片输入，不直接等同于数据库资产 ID。
- 模板解析请求只需要 `imageIds`，不需要携带 `filePath` 或 `dataUrl`。
- `PromptImageInput[]` 在真正调用生成适配器时使用，用于把 `imageIds` 映射到文件路径或图片数据。
- 后续接入资产管理后，`imageIds` 可以自然替换为持久化资产 ID。

这样 v1 可以先跑通图片变量，而不用提前完成完整素材库。

## 数据模型

建议在 `packages/shared/src/prompt.ts` 中逐步扩展模型。

```ts
export type PromptVariableType = 'text' | 'image'

export type PromptVariableBase = {
  key: string
  label: string
  required: boolean
  description?: string
}

export type PromptTextVariable = PromptVariableBase & {
  type: 'text'
  defaultValue?: string
  placeholder?: string
}

export type PromptImageVariable = PromptVariableBase & {
  type: 'image'
  maxCount?: number
  role?: 'reference' | 'character' | 'style' | 'composition'
}

export type PromptVariable = PromptTextVariable | PromptImageVariable

export type PromptPreviewImage = {
  url: string
  alt?: string
}

export type PromptSourceSite = 'youmind' | 'manual' | 'other'

export type PromptTemplate = {
  id: string
  title: string
  content: string
  description?: string
  categories: string[]
  variables: PromptVariable[]
  sourceSite: PromptSourceSite
  sourceUrl?: string
  sourceAuthor?: string
  originalSourceUrl?: string
  originalLanguage?: string
  previewImages: PromptPreviewImage[]
  createdAt: number
  updatedAt: number
}

export type PromptTemplateDraft = Omit<PromptTemplate, 'id' | 'createdAt' | 'updatedAt'>
```

生成时的变量值可以使用独立结构：

```ts
export type PromptVariableValue =
  | {
      key: string
      type: 'text'
      value: string
    }
  | {
      key: string
      type: 'image'
      imageIds: string[]
    }

export type PromptImageInput = {
  id: string
  name?: string
  filePath?: string
  dataUrl?: string
}

export type ResolvePromptTemplateRequest = {
  templateId: string
  values: PromptVariableValue[]
}
```

注意：`ResolvePromptTemplateRequest` 不传 `PromptImageInput[]`。模板解析只关心变量是否填写、图片数量是否满足规则，以及占位符如何解析。`PromptImageInput[]` 只在后续生成请求中使用。

解析结果建议包含用户预览和生成请求两个版本：

```ts
export type ResolvedPromptTemplate = {
  prompt: string
  previewPrompt: string
  imageInputs: Array<{
    variableKey: string
    role?: PromptImageVariable['role']
    imageIds: string[]
  }>
}
```

## 数据库设计

如果继续沿用 `prompts` 表，可以新增 `variables_json` 字段：

```sql
ALTER TABLE prompts ADD COLUMN variables_json TEXT NOT NULL DEFAULT '[]';
```

但从产品语义上，更推荐后续将表命名调整为 `prompt_templates`：

```sql
CREATE TABLE IF NOT EXISTS prompt_templates (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  description TEXT,
  source_site TEXT NOT NULL,
  source_url TEXT,
  source_author TEXT,
  original_source_url TEXT,
  original_language TEXT,
  categories_json TEXT NOT NULL DEFAULT '[]',
  variables_json TEXT NOT NULL DEFAULT '[]',
  preview_images_json TEXT NOT NULL DEFAULT '[]',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_prompt_templates_updated_at
  ON prompt_templates(updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_prompt_templates_source_url
  ON prompt_templates(source_url);
```

注意：`source_url` 不应再使用唯一索引。

原因：

- URL 只是填充来源，不是模板唯一身份。
- 用户可能基于同一个外部提示词创建多个变体。
- 用户可能抓取 URL 后大幅修改模板内容。

如果检测到相同 `sourceUrl` 已存在，可以在 UI 中提示：

```txt
这个链接已经创建过模板，仍然继续保存？
```

但不应默认阻止。

### 迁移策略

如果现场已经存在 `prompts` 表，需要优先保证升级不丢数据。

推荐迁移路径：

```txt
旧 prompts
  -> 新 prompt_templates
  -> 旧记录 variables_json = []
  -> source_url 不再唯一
```

迁移步骤建议：

1. 创建新的 `prompt_templates` 表。
2. 将旧 `prompts` 数据复制到 `prompt_templates`。
3. 旧数据的 `variables_json` 写入 `[]`。
4. 旧数据的 `source_site` 按原字段保留；无法判断时使用 `other`。
5. 确认迁移成功后，应用查询切到 `prompt_templates`。

如果短期继续沿用 `prompts` 表，需要：

- 新增 `variables_json` 字段，默认值为 `[]`。
- 删除旧的 `source_url` 唯一索引。
- 改为普通索引，保留按来源查询能力。

SQLite 不能直接 `ALTER TABLE DROP CONSTRAINT`，如果唯一索引是独立 index，可以使用：

```sql
DROP INDEX IF EXISTS idx_prompts_source_url;

CREATE INDEX IF NOT EXISTS idx_prompts_source_url
  ON prompts(source_url);
```

如果唯一约束内嵌在建表语句里，需要采用“建新表、复制数据、替换旧表”的迁移方式。

示例：

```sql
CREATE TABLE prompts_new (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  description TEXT,
  source_site TEXT NOT NULL,
  source_url TEXT,
  source_author TEXT,
  original_source_url TEXT,
  original_language TEXT,
  categories_json TEXT NOT NULL DEFAULT '[]',
  variables_json TEXT NOT NULL DEFAULT '[]',
  preview_images_json TEXT NOT NULL DEFAULT '[]',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

INSERT INTO prompts_new (
  id,
  title,
  content,
  description,
  source_site,
  source_url,
  source_author,
  original_source_url,
  original_language,
  categories_json,
  variables_json,
  preview_images_json,
  created_at,
  updated_at
)
SELECT
  id,
  title,
  content,
  description,
  source_site,
  source_url,
  source_author,
  original_source_url,
  original_language,
  categories_json,
  '[]',
  preview_images_json,
  created_at,
  updated_at
FROM prompts;

DROP TABLE prompts;
ALTER TABLE prompts_new RENAME TO prompts;

CREATE INDEX IF NOT EXISTS idx_prompts_updated_at
  ON prompts(updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_prompts_source_url
  ON prompts(source_url);
```

## IPC 设计

推荐将“导入”命名调整为“填充”或“抓取草稿”。

### shared channel

```ts
prompt: {
  fillFromUrl: 'prompt:fill-from-url',
  saveTemplate: 'prompt:save-template',
  listTemplates: 'prompt:list-templates',
  resolveTemplate: 'prompt:resolve-template',
}
```

### ElectronApi

```ts
fillPromptTemplateFromUrl: (url: string) => Promise<PromptTemplateDraft>
savePromptTemplate: (draft: PromptTemplateDraft) => Promise<PromptTemplate>
listPromptTemplates: () => Promise<PromptTemplate[]>
resolvePromptTemplate: (request: ResolvePromptTemplateRequest) => Promise<{
  prompt: string
  previewPrompt: string
  imageInputs: Array<{
    variableKey: string
    role?: PromptImageVariable['role']
    imageIds: string[]
  }>
}>
```

这里的 `prompt` 等同于 shared 解析结果里的 `generationPrompt`。IPC 层可以保留较短字段名，shared 纯函数内部使用更明确的 `generationPrompt`。

如果为了兼容已有实现，也可以先保留旧方法名，在内部转发到新的服务方法。

## Main Process 设计

### PromptFillService

原 `PromptImportService` 可以改名或逐步替换为 `PromptFillService`。

职责：

- 校验 URL。
- fetch 页面。
- 解析标题、描述、prompt、预览图和来源信息。
- 返回 `PromptTemplateDraft`。
- 不直接保存。
- 不处理 source URL 去重。
- 返回的远程预览图只作为 URL 元数据，renderer 展示时需要提供加载失败占位。

### PromptTemplateService

职责：

- 校验模板基础信息。
- 校验变量定义。
- 保存模板。
- 查询模板列表。
- 根据变量值解析模板。

校验规则：

- `title.trim()` 不能为空。
- `content.trim()` 不能为空。
- `variables` 必须是数组。
- 变量 key 必须唯一。
- 变量 key 必须符合命名规则。
- prompt 正文中出现的 `{{key}}` 应该能在变量列表中找到。
- 必填变量在生成前必须有值。
- 保存模板时强制校验 `content` 中所有 `{{key}}` 都已定义。
- 保存模板时强制将变量 key 归一化为小写。
- `maxCount` 缺省时按 1 处理。
- 解析模板时兜底校验 `imageIds.length <= maxCount`，即使前端控件已经限制上传数量。

### 共享解析工具

模板变量提取、key 校验和基础解析规则建议放在 `packages/shared`，让 renderer 和 main process 共用。

建议提供核心签名：

```ts
// packages/shared/src/promptParser.ts
extractPromptVariableKeys(content: string): string[]
validatePromptVariableKey(key: string): boolean
normalizePromptVariableKey(key: string): string
findUndefinedPromptVariables(content: string, variables: PromptVariable[]): string[]

export function resolvePromptTemplateContent(
  content: string,
  variables: PromptVariable[],
  values: PromptVariableValue[],
): {
  generationPrompt: string
  previewPrompt: string
  imageVariableMappings: Array<{
    variableKey: string
    role?: PromptImageVariable['role']
    imageIds: string[]
  }>
  errors: string[]
}
```

这样可以保证：

- 编辑器高亮和保存校验一致。
- renderer 预览和 main process 解析一致。
- 后续测试可以直接覆盖 shared 里的纯函数。

## Renderer 设计

建议将提示词管理页拆成两个核心场景：

```txt
模板库
  - 列表视图
  - 画廊视图
  - 搜索 / 筛选
  - 复制 / 使用

模板编辑器
  - 新建模板
  - 从 URL 填充
  - 编辑 prompt
  - 编辑变量
  - 保存
```

### PromptTemplateEditor

状态建议：

```ts
const [draft, setDraft] = useState<PromptTemplateDraft>(emptyDraft)
const [urlToFill, setUrlToFill] = useState('')
const [filling, setFilling] = useState(false)
const [saving, setSaving] = useState(false)
const [error, setError] = useState<string | null>(null)
```

编辑器能力：

- 输入 prompt 正文。
- 自动检测 `{{key}}`。
- 对未定义变量给出提示。
- 支持手动添加变量。
- 支持从 prompt 中一键生成缺失变量。
- 保存前校验变量定义。

### PromptVariablePanel

变量列表展示：

```txt
{x} name · 名字                 REQUIRED   text
{x} reference_image · 参考图     REQUIRED   image
```

变量编辑字段：

- key
- label
- type
- required
- defaultValue 或图片 role
- description

### PromptUsePanel

使用模板时展示：

```txt
模板标题
变量填写表单
最终 Prompt 预览
生成按钮
```

生成按钮禁用条件：

- 有必填文本变量为空。
- 有必填图片变量未选择图片。
- 图片数量超过变量 `maxCount`。
- prompt 解析失败。

最终 Prompt 预览建议使用 `previewPrompt`，而不是直接展示 generation prompt。这样图片变量可以显示为 `【参考图：已选 N 张】`，用户能确认图片变量已生效。

图片数量限制需要两层处理：

- 前端上传 / 选择控件直接受 `maxCount` 限制，最多只能选择 N 张。
- `PromptTemplateService.resolveTemplate` 仍做兜底校验，防止绕过前端或历史数据异常。

## 错误处理

URL 填充：

- URL 为空：请输入链接。
- URL 不合法：链接格式不正确。
- 暂不支持该来源：当前链接暂不支持自动填充。
- 网络失败：无法读取网页，请稍后重试。
- 页面结构不匹配：没有解析到可用提示词内容。

模板保存：

- 标题为空：请输入模板标题。
- Prompt 为空：请输入 Prompt 内容。
- 变量名不合法：变量名只能包含英文、数字和下划线，并以英文开头。
- 变量重复：存在重复变量名。
- 未定义变量：Prompt 中存在尚未定义的变量。
- 保存时未定义变量属于强校验错误，必须补齐变量定义后才能保存。

模板使用：

- 必填文本变量为空：请填写必填变量。
- 必填图片变量为空：请添加必填参考图。
- 图片数量超出限制：请减少图片数量。

预览图展示：

- 远程图片加载失败：显示低强调占位图，不影响模板保存和使用。

## 实施顺序建议

1. 新增 shared prompt variable 类型。
2. 在 shared 中新增变量提取、key 校验和模板解析纯函数。
3. 制定数据库迁移：新增 `variables_json`，或迁移到 `prompt_templates` 表。
4. 移除后续对 `source_url` 唯一性的依赖，并处理旧唯一索引。
5. 将 URL 导入服务语义调整为“从 URL 填充草稿”。
6. 新增模板保存和变量强校验逻辑。
7. 在 renderer 新增模板编辑器。
8. 在 prompt 正文中检测 `{{key}}` 变量。
9. 新增变量列表和变量编辑 UI。
10. 在生成前新增变量填写面板。
11. 将文本变量解析为最终 prompt。
12. 将图片变量转成结构化参考图输入。
13. 为远程预览图增加加载失败占位。
14. 运行 `pnpm typecheck`。
15. 运行 `pnpm --filter @art-pilot/desktop exec vite build`。

## 产品总结

提示词管理应从“保存外部提示词”升级为“管理可复用生成模板”。

URL fetch 是提高录入效率的工具，不是产品核心。

变量体系才是提示词模板的核心能力：

```txt
静态提示词
  -> 可填写模板
  -> 可复用生成工作流
```
