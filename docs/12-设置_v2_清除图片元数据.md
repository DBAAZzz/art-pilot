# 清除图片元数据

## 背景

Codex 生成图片可能携带文件级元数据，例如：

- EXIF
- XMP
- ICC profile
- PNG textual / ancillary chunks
- C2PA manifest

如果 Art Pilot 在导入图片库时直接 `rename` 或 `copyFile`，这些元数据会被完整保留，后续上传到平台时可能被检测出来。

本方案目标：Art Pilot 图片库保存的是可发布的干净版本，而 Codex 原始文件只作为临时输入来源。

## 产品设置

在设置页新增开关：

```txt
清除图片元数据
```

默认值：

```txt
开启
```

语义：

- 开启：Codex 图片导入图片库时，重新编码生成一张干净图片。
- 关闭：保留当前行为，直接移动或复制 Codex 原始文件到图片库。

推荐默认开启，因为多数用户期望图片库中的文件可以直接发布。

## 核心决策

清除元数据不采用“删除若干字段”的方式，而是采用像素重编码：

```txt
Codex 原始图片
  -> 解码为像素
  -> 重新编码为新图片
  -> 写入 Art Pilot 图片库
```

原因：

- EXIF、XMP、C2PA、PNG chunks 都属于容器级数据。
- 直接移动或复制文件会保留这些数据。
- 重编码默认只保留像素内容，不写回原始 metadata。
- 对 PNG / JPEG / WebP 都更稳定，不依赖特定字段名。

## 实现落点

当前导入逻辑位于：

```txt
apps/desktop/electron/services/imageLibraryService.ts
```

现有流程：

```txt
moveImageToLibrary
  -> createAvailableTargetPath
  -> safeMoveImage
  -> nativeImage 读取尺寸
  -> 返回 ImportedImage
```

调整后流程：

```txt
moveImageToLibrary
  -> createAvailableTargetPath
  -> 根据设置判断是否清除元数据
  -> sanitizeImageToLibrary 或 safeMoveImage
  -> nativeImage 读取尺寸
  -> 返回 ImportedImage
```

建议新增服务：

```txt
apps/desktop/electron/services/imageSanitizerService.ts
```

职责：

```ts
sanitizeImage(input: {
  sourcePath: string
  targetPath: string
  outputFormat: 'png'
}): Promise<void>
```

## 推荐技术方案

使用 `sharp` 在主进程中解码并重新编码图片。

示例：

```ts
await sharp(sourcePath)
  .rotate()
  .png({
    compressionLevel: 9,
    adaptiveFiltering: true,
  })
  .toFile(targetPath)
```

关键规则：

```txt
不要调用 .withMetadata()
```

Sharp 默认不会把 EXIF、XMP、C2PA 等元数据写入新文件。PNG 的 ancillary chunks 也会在解码再编码过程中被丢弃。

## 输出格式

第一版建议统一输出 PNG：

```txt
source: .png / .jpg / .jpeg / .webp
target: .png
```

原因：

- Codex 当前主要输出 PNG。
- PNG 无损，适合默认保存生成图。
- 统一格式便于后续预览、缩略图、平台上传前检查。

如果未来需要保留源扩展名，可以再扩展为：

```txt
png -> png
jpeg -> jpeg
webp -> webp
```

但第一版不建议增加复杂度。

## 设置与共享类型

新增设置字段：

```ts
stripImageMetadata: boolean
```

默认值：

```ts
true
```

建议改动范围：

1. `packages/shared/src/settings.ts`
   - `AppSettings` 新增 `stripImageMetadata`
   - `UpdateAppSettingsRequest` 新增 `stripImageMetadata`
2. `apps/desktop/electron/services/settingsService.ts`
   - 新增 settings key
   - 读取默认值为 `true`
   - 支持更新 boolean 值
3. `apps/desktop/src/features/Setting/StoragePanel/index.tsx`
   - 新增「清除图片元数据」开关
   - 默认展示为开启
4. `apps/desktop/electron/services/imageLibraryService.ts`
   - 导入时根据设置选择 `sanitizeImage` 或 `safeMoveImage`

## 导入失败策略

当「清除图片元数据」开启时：

```txt
sanitize 失败 = 导入失败
```

不建议自动 fallback 到 `safeMoveImage`，因为 fallback 会把原始元数据重新带入图片库，违背用户打开开关后的预期。

失败时应：

- 标记任务为错误或记录单张图片导入失败。
- 保留 Codex 原始文件，便于排查。
- 错误信息明确提示“图片元数据清除失败”。

## Codex 原图清理关系

现有设置：

```txt
Codex 原图清理：不删除 / 导入后删除
```

新设置与它互相独立：

```txt
清除图片元数据 = 控制图片库文件是否重编码为干净版本
Codex 原图清理 = 控制导入成功后是否删除 Codex 原始文件
```

推荐组合：

```txt
清除图片元数据：开启
Codex 原图清理：导入后删除
```

这样图片库只保留干净文件，Codex 临时目录也不会长期保留原始文件。

## 验证方式

实现后需要验证：

1. 开关默认开启。
2. 开启时导入后的图片不包含 EXIF/XMP/C2PA。
3. 关闭时仍走原有移动逻辑。
4. 清洗失败不会生成半成品文件。
5. `pnpm typecheck` 通过。
6. `pnpm --filter @art-pilot/desktop exec vite build` 通过。

可选本地验证命令：

```bash
exiftool path/to/image.png
```

期望导入后的图片不再显示原始 EXIF、XMP、C2PA 相关字段。

## 边界说明

本功能清除的是文件级元数据：

- EXIF
- XMP
- C2PA manifest
- PNG textual chunks
- 其他容器级 metadata

它不保证移除：

- 像素级水印
- 生成模型留下的视觉特征
- 平台基于账号、来源、上传行为的检测
- 平台基于图像内容本身的 AI 生成检测

因此，「清除图片元数据」应被描述为发布前的文件清洁能力，而不是规避所有平台检测的保证。
